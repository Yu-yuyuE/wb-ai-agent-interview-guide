# AI Agent 面试简答版（400 题 · 口述答案 + 面试官追问）

> **定位**：详解版用来查漏补缺、搞懂原理；这一版只解决一件事——**进面的 60 秒里，开口就能说对**。每题都是「面试官提问 → 我（60 秒口述）→ 面试官追问 → 简答」的对话体，答案按技术面试的评分口径写：结论先行、讲机制与取舍、落到工程动作、点出代价或边界，不说空话。
> **覆盖范围**：JavaGuide `docs/ai` 四篇题目页 213 道 + 项目实战自测与入口页高频 63 道 + 小林面试笔记 6 专题 124 道 = **400 道**，逐题给口述答案；共 **801 组**面试官追问与回答。
> **资料来源**：[Snailclimb/JavaGuide · docs/ai](https://github.com/Snailclimb/JavaGuide/tree/main/docs/ai)（2026-11-09 抓取）、[小林面试笔记 · 大模型面试题](https://xiaolinnote.com/ai/)（2026-11-11 抓取）；答案依据两套题库与详解版重新组织，**不是原文转载**。
> **口径提醒**：涉及模型版本、上下文窗口、框架 API、Tokenizer 词表与部署参数的具体数值会变化，面试与落地请核对官方文档；文中不编造项目 QPS、准确率等业务数据。

## 0.1 怎么用这一版

1. **自测**：打开附录 A 的 400 题清单，遮住答案，每题限时 60 秒口述，能说出「结论 + 2 个要点 + 1 个落地细节」再打勾。
2. **回查**：卡住的题按 ID 回对应部分精读；想深挖原理，去详解版 `AI-Agent面试指南.md` 用题干或 ID 检索。
3. **压面**：让同伴只念「追问 1 / 追问 2」，练接招；追问都问在「为什么、怎么落地、出过什么问题、代价是什么、怎么验证」上，正是真实面试的追法。
4. **考前一天**：只看 0.3 口述公式 + 0.4 追问套路 + 第三部分项目实战，不再通读。

**为什么要练追问**：面试官判断你是否真做过，靠的是第三层追问。只背结论的人在第一层就停了；能接住「写操作超时你怎么知道有没有执行」「换模型后怎么证明不是 Prompt 的锅」这类问题，才说明有工程判断。

## 0.3 面试口述的万能公式

**① 概念题（是什么 / 区别）**：一句话下定义 → 讲清它解决的具体问题 → 点一个易混淆边界 → 落到工程影响。

> 例：「RAG 不是把文档塞进 Prompt，是先检索证据再生成；它解决的是知识时效和私有数据，不解决模型行为；和微调的边界是补知识 vs 改行为；工程上真正的难点在召回质量和权限过滤。」

**② 为什么这么设计**：约束 → 候选方案 → 选择理由 → 代价 → 验证证据 → 何时换方案（六问）。

**③ 排查题**：固化现场 → 分层假设（数据 / 检索 / 上下文 / 模型 / 工具 / 编排）→ 控制变量 → 可复现根因 → 在正确的一层修 → 原 Case + 相邻边界 Case 进回归集。

**④ 系统设计题**：场景与成功标准 → 约束容量 → 一次请求链路 → 分层职责与「不能交给模型」的部分 → 状态与恢复 → 安全审计 → 观测评测 → 灰度回滚 → 瓶颈与演进。

**⑤ 项目 / Badcase 题**：现象与影响 → 证据（Trace、评测集、版本）→ 根因 → 修复放在哪一层 → 代价 → 回归用例与线上指标。

**共同禁忌**：只报技术栈、只说「效果很好」、把超时当失败、把 Schema 校验当授权、把 Chat History 当长期记忆、动辄 Multi-Agent。

## 0.4 追问的四类套路与接法

| 追问类型 | 典型问法 | 接法 |
| --- | --- | --- |
| 追原理 | 「为什么会这样，不是靠 Prompt 兜住就行吗？」 | 回到机制，讲失效条件，再给工程兜底 |
| 追落地 | 「线上真这么做了吗，出过什么问题？」 | 讲字段、参数、幂等键、Trace、降级路径，不编造数字 |
| 追代价 | 「这么设计引入了什么新问题？」 | 主动说延迟 / 成本 / 一致性 / 调试复杂度，再给控制手段 |
| 追边界 | 「约束变了 / 模型升级 / 流量十倍，你还这么选吗？」 | 给明确的切换条件，并说明换方案要重跑哪些评测 |

**接不住时的正确姿势**：先说清已知边界（「这块我没有生产数据，能说的是设计取舍」），再给出可验证的思路，不要现场编造 QPS、准确率或事故。
